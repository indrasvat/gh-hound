Follow a live run by its steps

From a user report: “Can it follow a live run? It shows Run tests as queued but it's running.” GitHub serves a job's log only once the job finishes, and has no API for a running one. So hound now follows a running job by its steps. Same keys, same fixture, same moment on both builds. Top or left is main d3b625e with the new live_run fixture copied in; bottom or right is this PR.

Fixtures · PTY scenarios at 80x24

Is there a streaming log API?

  • GET /actions/jobs/{id}/logs on a running job redirects to a blob that answers 404 BlobNotFound until the job finishes. No partial or growing file.
  • The per-step logs endpoint now in the REST docs answered 404 on running and finished jobs alike (tested 2026-10-20).
  • The web UI's live log uses an undocumented alive.github.com websocket that needs a browser session, not a token. cli/cli#3484 has been open and blocked since 2021, and gh declined to scrape it.
  • Steps' status and timestamps are live on the jobs endpoint. That is what hound follows.

Review

  • Two adversarial agents drove the real app and binary. Detail: the poll never refreshed the run (polling stopped early, a late job never showed, an approved gate never cleared), a queued job with started_at showed a clock, a stale poll could land after reopening. Watch: no height bound, multiline step names. All fixed.
  • Security review: GitHub names reached the terminal raw; a job name can carry a fork PR's title. The adapter now drops control and bidi-override runes. Pre-existing, fixed here.
  • dootsabha council (codex, agy; grok could not start its sandbox): five findings, all fixed. A failed first load now heals on the poll, the poll identity carries the opening, a finished run with no jobs stops polling, l on a jobless live run toasts, and the step clock only runs for a running step.
  • Cold tui-qa, round 1: FAIL. The watch block was a fixed three lines at any height, a long name cut the toast hint, clocks read 17.0s vs 17s, and a queued job's steps pane was empty. Round 2: PASS, including live 9- and 86-job runs at every size and a failed load healed through a failing proxy.
  • Live check (rust-lang/rust) found two more, both fixed: the running step sat under +18 more, and l during a slow job listing claimed “no job has started yet”.
  • Recorded, not changed (also on main): the detail jobs list never scrolls, so on an 88-job run the selection walks off the frame (needs its own task). A detail load failure is titled Runs unavailable. The watch follow tail is six lines.
